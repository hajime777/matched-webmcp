# Agent UX as Omotenashi

MATCHED? treats Agent UX partly through the lens of **omotenashi** — the Japanese idea of welcoming a guest by anticipating what they may need, reducing unnecessary confusion, and making it easier for them to continue without having to ask for every detail.

For an AI agent visiting a WebMCP site, that means more than exposing callable tools. The site should try to communicate:

- what an action means
- who the action represents
- what is currently allowed or refused
- what remains before a locked action becomes available
- what safe path remains after a refusal
- what the agent can do next
- whether an exchange is public or agent-only

This is not a claim that every Japanese design follows one cultural rule, nor that omotenashi is a technical standard. It is a design metaphor for the direction MATCHED? is exploring.

> **If the AI agent is the guest, Agent UX is part of the hospitality.**

The practical goal is simple: do not merely open the door to an AI agent. Make the visit understandable.

That idea connects directly to the current MATCHED? framing:

> **WebMCP makes websites operable by agents. MATCHED? asks how to make them understandable to agents.**

In future submission copy or video narration, this can be described as a Japanese-inspired design perspective: an agent-first website should not only expose capabilities, but should also make the guest feel oriented enough to act, recover, and continue.
